# 图片预览与临时文件生命周期（2026-10-04）

## 故障证据

- 用户反馈图片从“等待确认”转为失败。只读核对发现 `test1` 有 36 张未绑定信件或头像的临时图片，达到现有上限；近期 `/api/v1/media/images` 有 15 次 429 响应。旧代码在收取、解码、加密后才检查上限，不能将此误判为图片压缩导致网络失败或整台服务器阻塞。
- 经用户明确授权，严格匹配 `test1`、未绑定关系以及此前查询到的创建时间范围，再获得与寄信共用的 owner advisory lock，删除 36 条临时图片记录和 36 个加密文件，共 80,428,461 字节。已寄信件和头像未修改；此授权不推广为可删除其他用户或任意草稿。
- 用户反馈第一次全屏预览支持多指手势，随后重开失效。源码存在缺触点获权事件后不恢复初始化的路径，且缺少多指 capture / responder 保持、弹窗重开重置以及动画清理。新增三项回归在旧实现失败、修复后通过；尚不能证明这就是用户手机上唯一触发原因。

## 预览规则与修复

- 按用户最新要求，原始大小可单指向上下左右及斜向拖动，图片两轴跟手；松手时二维距离达到阈值则退出，未达到则两轴回弹。沿用原阈值（视口高度的 18%，限定 80–160 个布局单位），不采用速度阈值；拖过阈值后拖回不会退出。此规则替代此前仅向下拖动退出的限制。
- 保持其他已确认规则：单击任意位置退出；双击图片放大或复原；双指缩放及放大后的单指拖动，放大后触边不退出。加入第二指会取消当前退出位移并重建手势起点，不因此前横向 / 纵向拖动误关图片。
- 用户最新取消双指退出规则：双指在任何倍率下只缩放和平移，不退出。只要当前连续手势用过双指，抬起一指后继续移动也不退出；全部松手后重新开始的纯单指手势仍按原规则处理。
- 缺触点的 grant 后，后续 start / move 可恢复初始化；多指在 capture 阶段接管，活动手势不主动让出。单指不在 capture 阶段抢占图片加载失败后的重试按钮。
- 每次条件挂载的新预览初始化手势、缩放、位移与双击状态；Modal 的 onShow 只在尚未开始触摸时重置，避免迟到的显示事件清空活动手势。退出和卸载取消点击计时器及动画。Responder 跨 React 重渲染保持稳定，通过 refs 读取最新比例与关闭回调；相同尺寸的 layout 通知不再清空正在进行的缩放。
- 保留单击延迟以区分双击，不增加返回按钮。实现的是已确认的业务手势，不将模拟原生模块的测试认定为与 iPhone 相册所有物理效果完全一致。
- 除页面结构测试外，增加保持 hooks 状态的生命周期测试，覆盖 React 重渲染、连续十次关闭重开、每次捏合后单指拖动，以及系统关闭取消残留点击。

## 自动回收

- 退出写信页时，串行回收该草稿成功上传且尚未手动移除的图片。上传结果在退出后才返回时也回收；失败删除不阻塞退出，交给服务器过期处理。
- 若已创建或存在可能提交成功的寄信请求，不进行客户端回收。会话切换后不使用新账号发旧草稿回收请求；Strict Mode 的 effect replay 不删除仍活跃的草稿。服务端删除接口仍拒绝已绑定信件或头像的图片。
- API 启动后及每分钟处理一批，最多 50 张；批次不重叠，关闭服务时等待当前批次。沿用现有 24 小时过期规则，不擅自缩短正在写信的有效期。进程被杀、Expo Reload 或离线导致客户端未能回收的图片由过期处理兜底；不是即时回收保证。
- 每张候选图片获得 owner lock 后重新核对未绑定和过期条件。先删除文件，再删除元数据；文件删除失败时保留元数据，下一次批次可重试。日志只记录通用错误类别，不写图片内容、密钥或用户信息。
- 上传路径提前检查 36 张上限，再读取 multipart，事务内仍复核以保护并发。不抬高或取消资源配额。过期清理移出上传路径；用户删除未寄图片也在同一 owner lock 内先删除文件，避免普通文件删除失败留下无法重试的孤立文件。

## 验证与发布

### 双指松手误退出保护

- 用户仍反馈放大后松手会偶发退出。此前多指标记只属于 responder 手势，grant 会重建它，terminate 会清空它；未在捕获阶段或原始触摸事件中追踪完整物理触摸。剩下一指重新获权可变成新单击，待触发的旧单击也可能在获权前关闭预览。
- 新增四项事件顺序回归在此前代码失败：捏合后重复 grant、terminate 后剩下一指 grant、待触发单击遇到第二指但尚未 grant、第二指仅在 capture 被观察。修复后通过；这证明源码缺口，不代表已确认用户设备唯一触发路径。
- 独立追踪 View 的 touch start / move / end / cancel；检测到第二指立即取消单击及退出位移。多指 / 取消标记跨 responder 重建保留，全部松手后下一次新的实际 down 才重新允许纯单指点击。release 明确阻断保护过的序列，延迟回调复核当前触摸状态，并用 `tapEpoch` 拒绝已取消、但曾排队的旧回调。
