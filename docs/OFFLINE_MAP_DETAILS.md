日期：2026-10-04。状态：本机实现及自动化复验；未同步服务器、未重新打 APK。新增数据的上游再分发权利和地图公开发布审核仍为 pending。

## 显示层级

| 地图缩放   | 背景内容                                         |
| ---------- | ------------------------------------------------ |
| 小于 6     | 原有全国陆地区域填色及避让后的省名；清除详细图层 |
| 6 至小于 9 | 视口涉及省份的市级边界、城市名称                 |
| 9 至 13    | 上述内容加区县边界、区县名称                     |

背景颜色只帮助辨认行政区域，不表达信件状态。城市名称和区县名称会避让业务标记、业务标签、顶部进度及底部控制，重叠时省略，放大或平移后重新排布。不伪造街道、实际运输道路或手机定位。

根据预览反馈，删除旧省级低精度实线描边图层，并关闭基础填色图层的描边，避免放大时与详细市级/区县边界重叠。源几何仍保留用于全国填色、标签和全图适配；不改运输路线。

### 水系精度门禁

用户要求水系与行政区划具有一致的细节程度，尤其黄浦江与浦东沿江区界不能错位。当前 Natural Earth 1:10m 数据无法证明满足这一要求，已停用其解码、注入和显示，不以平滑、补点或强制吸附制造高精度；历史候选仍保留在固定资产和来源报告，便于追溯。

经用户确认，上海试点同时替换为同源 OSM 区界和河面多边形，详细来源、生成与复验见 [上海同源水系试点](SHANGHAI_HYDROLOGY.md)。其他省份尚未完成同源替换，仍不显示旧粗略水系。不能据此宣称全国水系已完成或达到官方测绘精度。

业务路线仍来自已经过滤的服务端 DTO。公共区域名称不能用于补全收件人不可见的起终点、未来驿站、剩余路线或预计位置；本轮没有更改正文、图片、时间戳和运输事实权限。

## 来源与覆盖

详细来源、输入 SHA-256、逐项拒绝记录和缺失列表见 [资产报告](../data/maps/detail-source-report.json)；地图源登记见 [data/maps](../data/maps/README.md)。

- 行政区域来自 [ChinaAdminDivisonSHP](https://github.com/GaryBikini/ChinaAdminDivisonSHP)，固定版本 `ae72417fee2a63f453e6b2717e40655e87e26887`、版次 `v24.02.06`。仓库采用 MIT，但上游来自高德行政区域数据，不能据此宣称已取得独立再分发权利或满足地图发布要求。
- 实际源坐标为 GCJ-02；生成时使用 gcoord 转换为 WGS84，再与现有 Leaflet Mercator 底图统一显示，运行时不调用转换 API。
- 按项目地区选择器的编号、名称、省份与区县所属市精确匹配。不匹配的 46 个源条目不纳入；没有模糊改名或手绘边界补齐。
- 目前匹配 364 个市级条目、2839 个区县；选择器仍有 217 个区县缺少该背景形状。市级条目包含选择器中的省直管区域，不等同于新增了 364 个运输驿站。
- 上海背景覆盖 16 个区，包含黄浦、浦东、闵行和金山，不包含旧卢湾、闸北、南汇名称。**这不改变后端候选代表点库**：后者仍匹配 14/16，闵行和金山端点缺失，不能将背景覆盖当作业务端点已经补齐。
- 历史水系候选来自 [Natural Earth 1:10m](https://www.naturalearthdata.com/downloads/10m-physical-vectors/10m-rivers-lake-centerlines/)，固定版本 `ca96624a56bd078437bca8184e78163e5039ad19`，保留 258 个要素用于来源追溯，现已停用显示。[许可为 public domain](https://www.naturalearthdata.com/about/terms-of-use/)。这是小比例尺概略数据，不满足当前区县级水系精度要求。
- 原有 34 个省级源几何、冻结驿站图和路线距离保持不变。省级背景仅增加区域内标签代表点，不重画国界或岛屿。

MIT 完整通知保存在 `data/maps/source/ADMIN_DETAIL_LICENSE`；数据源、fflate、TopoJSON 的通知写入 `detailData/notices.json`，随 WebView HTML 分发，页面保留来源 attribution。地图公开发布与上游再分发审查仍须单独完成，当前只作本机候选验证。

## 体积与加载

- 分为 31 个省份的城市/水系包和区县包；使用 TopoJSON 共享边界、量化 1e6，再 deflateRaw + base64。
- 上海试点接入前的离线包与索引、通知合计 6,773,357 字节，约 6.46 MiB。新增上海同源包和 ODbL 通知另外随应用分发；上海使用原始坐标精度而不是 1e6 量化，避免细河面和孔洞失效。全国包仍随应用分发，并非从安装包中删除。
- 只解码视口相交的省份；详细数据不放入首次 WebView HTML，解码缓存最多保留 8 个包。只把相交要素注入背景图层。
- 视口变化防抖 100 ms，旧 request ID 的响应不会覆盖新视口。轮询只更新业务图层，不重新加载 WebView、不重置相机。
- 解码失败保留基础图并显示区域细节不可用状态。WebView 故障则沿用原静态省级兜底；静态兜底不宣称具备详细背景和交互能力。

## 生成与本机预览

生成器只读取固定哈希的本地源文件，不在构建或运行时下载。源 SHP/DBF 和 Natural Earth GeoJSON 放在忽略的 `.local` 目录；路径及校验值在资产报告中，重新生成前需从上述固定上游版本取得同一文件。

```sh
docker exec yishu-next-version-tools-1 node scripts/generate-geographic-map.mjs
docker exec yishu-next-version-tools-1 node scripts/generate-map-details.mjs
docker exec yishu-next-version-tools-1 pnpm --filter @yishu/api exec tsx ../../scripts/render-local-map-preview.ts
```

本机预览：`http://127.0.0.1:4179/geographic-map`，可切换全国、浙江省内、上海路线。这是测试示例，不是线上账号或真实信件；独立 HTML 只内置这些示例涉及的区域，移动端加载器包含上述全部 31 省份。

预览的上海路线为黄浦区 → 上海驿站 → 浦东新区，只有两段，不额外画同市城际线。浙江路线为宁波市海曙区 → 宁波驿站 → 杭州驿站 → 杭州市余杭区，分别显示起运、城际、末端三段。浙江示例使用当前背景的区内代表点，仅为测试，不覆盖后端历史区县锚点。

前端从已经过滤的 DTO 提取路段，对同时出现在路径和 `collection` / `delivery` 的连接去重，跳过同坐标的零长度线；不推断不可见端点或新路线。物流页标题优先显示 DTO 中的区级起终点，首段进行中显示“运输中”。
