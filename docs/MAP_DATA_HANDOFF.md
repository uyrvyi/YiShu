## 接收资料要求

1. 边界优先提供 GeoJSON、GeoPackage、Shapefile 或 File Geodatabase；附原始压缩包。必须包含完整多边形，不只提供经纬度点、截图或绘图参考。
2. 附地区正式名称、代码、所属省市、数据生效日期及具体范围口径；同名地区必须能够区分。记录原始坐标参考系与单位，不凭肉眼猜测 WGS84／GCJ-02 等坐标系。
3. 附发布机构、公开原始网址或提供证明、允许的使用与再发布条件；“网上能下载”不等于可任意修改或公开发布。
4. 如有审图或其他核验材料，提供适用产品、版本、用途及有效范围；来源底图的审核材料不能自动视为本项目的审核材料。
5. 不需要提供用户账号、信件正文、照片、恢复码或服务器密钥。取得文件后先存入隔离目录，计算 SHA，再核验内容，不执行下载包里的脚本。

## 收到后的技术处理

- 检查文件完整性、坐标系、行政身份、几何有效性、岛屿及完整范围，并与父区归属核对。不同来源之间水系／边界不能简单叠加后宣称一致。
- 更新逐项证据与源 SHA，再重生成正式地区清单、端点和新图；原 347 项仍逐项保留结论，不能用新条目替换未通过条目凑数。
- 全部共同上线的前置门禁完成后，运行 `check_endpoint_evidence.py --require-release`，然后按 [1.1 运单发布检查](TRANSPORT_1_1_RELEASE_CHECKLIST.md)执行隔离联调、备份、发布和 iPhone 复验。
- 没有取得的资料继续标记 pending。数据身份、几何质量、代码审查、正式地图核验及真机结果分别记录，不能互相代替。
