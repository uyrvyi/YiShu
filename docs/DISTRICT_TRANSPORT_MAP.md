## 业务规则

```text
寄件区县 -- 3 小时 --> 本市驿站 -- 原有运输规则 --> 目的市驿站 -- 6 小时 --> 收件区县
```

- 起终点使用区县代表点，不是用户住址、街道坐标或手机实时定位；中间驿站仍是市级。
- 首段 3 小时计入运输时长；末端继续沿用现有 6 小时，不擅自改变其他运输速度和随机事件。
- 同市不同区也需要经过本市驿站；没有城际路段时总计 9 小时。
- 黄浦区 → 上海驿站为“运输中”，上海驿站 → 浦东新区为“派送中”；只画两段。同省跨市路线也必须包含寄件区 → 起点市驿站和目的市驿站 → 收件区，两段不能因距离较短而省略。
- 新规则版本为 `1.1`。既有 `1.0` 信件、已送达记录和冻结路线不补算 3 小时。
- 收件人地图仅绘制可见事实，起运期间不展示未来市驿站、收件区县终点、预计位置或剩余路线；到达市驿站后再展示已确认连接，送达后才显示区县终点。未来时间事实仍按 `visibleAt` 过滤。
- 正文、图片与写信时间的既有送达可见性保持不变。寄件人独享参考预估。
- 起运期间修改收件地区，等到本市驿站时应用新目的地；城际在途继续等下一驿站，末端派送从最后市驿站立即重算；已送达信件不改。

## 地图实现

- 当前服务器采用 Leaflet 1.9.4 + 自有全国静态矢量瓦片 + 业务路线图层；JS/CSS 内置，无百度 SDK 或运行时坐标转换 API，按视野请求自有 HTTPS 静态文件，含主要道路、水系与行政边界，见 [全国静态地图](SELF_HOSTED_VECTOR_MAP.md)。本机离线背景方案的来源与历史覆盖限制见 [离线分级运输底图](OFFLINE_MAP_DETAILS.md)。底图部署不表示新的区县业务端点已启用。
- 交互底图使用 `EPSG:3857` 和原始 WGS84 GeoJSON；所有业务路线、驿站、区级端点先解码冻结 `mapX/mapY` 再统一投影，修复原来直接显示业务坐标导致的纵向拉伸。解码坐标仍是示意位置，不是用户 GPS 或实际道路导航。省级背景来源沿用 `data/maps/README.md`。
- 北向上，支持平移、双指缩放、缩放按钮和全程适配；首次适配只使用服务端给出的可见点，留出顶部进度栏和底部控件空间。
- 物流轮询只替换业务图层，保持 HTML/WebView 和用户的缩放、拖动视口；点击全程按钮才主动复位。
- 静态兜底也使用同一 Mercator 投影和等比拟合，不再使用失真的旧显示比例；缺区县数据时明示“区县位置暂缺”，不拿市坐标冒充区县。
- 新增全国底图按钮，与可见路线适配按钮分离；全国低缩放隐藏重叠的业务标签，放大后恢复。轮廓、岛屿和省界源几何不变，业务图和旧版本地图资产保持冻结。
- Leaflet 采用 BSD-2-Clause，完整许可随 `apps/mobile/src/map/vendor/LEAFLET_LICENSE` 分发。

## 启用与兼容

- `NEW_LETTER_RULES_VERSION` 默认 `1.0`，`.env.example` 同样保持 `1.0`。**本轮未启用生产新规则**。
- 数据覆盖、归属验证与发布审查通过后，备份数据库，应用 `20261004060000_district_collection` 迁移，部署 API/Worker/前端兼容版本，再把 API 环境设为 `NEW_LETTER_RULES_VERSION=1.1`。
- 迁移只新增可空 `Journey.originStationReadyAtSim`；旧行保持 NULL，不改旧信件时长。
- 起运锚点来自信件冻结寄出时间，即使晚初始化或一次跳过多天，也不会重新等待 3 小时。Worker/API 共用同一推进器。
- 新 DTO 的 `collection`、`delivery`、`stations` 和缺失地区列表为可选字段；旧 `1.0` 地图响应不增加字段。
- 上线后回退创建开关到 `1.0` 只影响后续新信件；已有 `1.1` 信件仍需保留新版推进器，不得直接回滚到不识别版本的旧 Worker。
- 云端 Expo Go 已单独发布地图显示补丁；区县运输的 API/Worker 未更新，数据库未迁移，APK 不变。不能将显示补丁当作 `1.1` 区县运输已上线。
